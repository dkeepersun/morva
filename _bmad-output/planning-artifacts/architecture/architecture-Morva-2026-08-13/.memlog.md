- (direction) Fast path selected by user; architecture spine, protocol draft, executable prototype, and real AI sample validation are all deliverables.
- (note) Brownfield constraints: morva-core owns all language semantics; CLI is presentation and file discovery only; existing text contracts and exit codes remain unchanged by this design.
- (decision) Paradigm is a deterministic projection pipeline: source input is parsed and checked once, then a read-only protocol projection is emitted; AI consumes the projection but never owns semantic truth.
- (decision) Protocol v1 is self-contained JSON with inline exact source bytes, source-local byte spans as authoritative provenance, deterministic ordering, and no timestamps or run-specific values.
- (decision) A protocol document with any error contains findings and sources but no semantic model; only an error-free check may emit checked_model, preventing partial ASTs from masquerading as validated semantics.
- (decision) Protocol evolution uses a major integer version and capability identifiers; v1 consumers ignore unknown object members but reject unknown major versions and must not infer semantics from unknown discriminants.
- (decision) AI revisions are new complete candidate source sets checked in a fresh run; the protocol defines no mutation, patch-apply, or auto-accept operation, preserving human-reviewed .morva as Source of Truth.
- (decision) Coverage gaps such as compatibility containers and soft behavior are first-class warning findings and coverage records; format validity never implies semantic completeness.
- (assumption) [ASSUMPTION] A future implementation may add SHA-256 source revision digests after dependency/change-control approval; the protocol draft binds the algorithm but this task does not add a production dependency.
- (assumption) [ASSUMPTION] Initial consumers are Morva CLI automation, AI tools, and later MCP/editor adapters; maintainers are the protocol approvers.
- (gap) No production protocol implementation is authorized in this design-validation task; the executable artifact is explicitly throwaway and validates state/shape only.
- (decision) Human review requires an evidence bundle containing original intent, accepted/base revision, full revised candidate, relevant check findings and coverage, and AI diagnosis/rationale; a green revised result alone is insufficient.
- (decision) Protocol v1 has five mandatory capabilities: inline sources, byte-range locations, findings v1, coverage v1, and checked-model v1; the schema enforces all five while allowing optional additions.
- (decision) JSON Schema validates protocol shape only; a morva-core-owned semantic-envelope validator must enforce range bounds, source references, status/finding consistency, and one-to-one coverage-warning correspondence.
- (decision) Current coverage detail payloads are discriminated and typed: compatibility container carries container_kind and name; action soft behavior carries action and behavior; consumers never parse messages for these facts.
- (event) Input reconciliation review found four gaps; all are accepted for correction before the reviewer gate.
- (event) All six positive protocol snapshots passed Draft 2020-12 schema validation after typed coverage reconciliation.
- (event) Five negative schema mutations were rejected: missing mandatory capability, valid with error, invalid without error, valid with unavailable coverage, and malformed known soft-behavior detail.
- (note) Schema validation is explicitly limited to shape; production protocol conformance additionally requires the designed morva-core semantic-envelope validator.
- (decision) The mandatory checked-model v1 capability uses a closed L0 semantic algebra for entity, enum, action, scenario, fields, members, parameters, clauses, assignments, runs, and all current expression/type variants; new semantic discriminants require protocol v2.
- (decision) Project-level diagnostics may use a subject-scoped primary location and an empty source bundle; source-local locations remain mandatory for source-owned facts. Pre-core IO/discovery failures emit no checked-semantics document and retain operational exit 2.
- (decision) Canonical source IDs are opaque source ordinals after core sorts project logical names by exact UTF-8 bytes; names are exact UTF-8 basenames with no Unicode normalization. Single-file subject/source name is the final path component supplied as a logical name separate from host path.
- (decision) A multi-file checked system carries ordered shell_locations for every source shell; it does not inherit the first shell as sole provenance.
- (decision) Language version is fixed to 0.1 for protocol v1. Unknown semantic discriminants or unsupported language versions fail closed for checked-model consumption; extra object members remain ignorable.
- (decision) Review lineage always compares a candidate to the current accepted revision using compare-and-swap; intermediate candidates cannot become a review base. Incomplete coverage requires an explicit per-item acknowledgement with out-of-scope or externally-evidenced disposition, otherwise the decision is block.
- (decision) Schema identifier is the non-resolving controlled URN urn:morva:schema:checked-semantics:v1; protocol normative words adopt BCP 14.
- (decision) Revision digests prove content identity/integrity only, not origin, authorship, authenticity, or human approval.
