# Story 3.2: 使用析取表达替代业务条件

Status: done

## Story

As a 业务规则作者,
I want 使用 `||` 表达多个可接受条件中的任意一个,
so that 我可以描述"VIP 或金额超过阈值"这类没有现有 workaround 的高频规则。

## Acceptance Criteria

见 `_bmad-output/planning-artifacts/epics.md#Story-3.2` 与冻结规格 `spec-boolean-disjunction.md`。

## Implementation Notes

- Lexer：`|` 进入 operator-start 集合，`||` 成为单一 operator token；注释拆分守卫泛化为 `SplitLeft::OperatorStart(char)`，覆盖 `|/*...*/|`。
- Parser：`expression()` 变为左结合析取层循环，原 `!`/括号/比较逻辑下沉为 `unary()`；`!` 递归进入 `unary` 保证 `!a || b` = `(!a) || b`。
- Checker：`Or` 两侧各自递归 `check_predicate`，右侧永远被检查；赋值/scenario 值路径与 `Not` 同规则；矛盾事实推导对 `Or` 返回 None（Story 3.3）。
- Simulator：确定的左到右短路求值；左 `true` 不读右侧状态，右侧失败 span 指向真正被求值的右路径。
- CLI 渲染 `a || b` 与 `!(a || b)`；能力清单声明短路左结合析取，unsupported 改列 `&&`。
